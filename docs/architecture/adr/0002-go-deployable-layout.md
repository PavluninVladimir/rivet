## Контекст

В репозитории `cmd/` есть несколько entrypoint'ов: `cmd/rivetd` (control plane),
`cmd/rivet-runner` (агент на машине пользователя), `cmd/rivet` (CLI) и
`cmd/fake-llm` (подставная модель для e2e). `docker-compose.yml` разворачивает
`rivetd`, PostgreSQL и объектное хранилище, а runner запускается вне compose —
на машине, где есть доступ к репозиторию.

## Решение

Держать контрольный процесс, runner и CLI отдельными Go-бинарниками.
Веб-консоль собирается из `internal/webui` и встраивается в `rivetd`, поэтому
отдельного фронтенд-сервиса в поставке нет. `fake-llm` — вспомогательный
процесс только для тестов, в продакшене не разворачивается.

## Последствия

- Control plane и runner обновляются независимо и разделяют только протокол.
- Runner видит репозиторий и песочницу пользователя, не поднимая их на сервере.
- CLI остаётся тонким клиентом к HTTP API, переиспользуя часть серверных пакетов.
