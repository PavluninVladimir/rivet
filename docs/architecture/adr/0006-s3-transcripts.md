## Контекст

Сессии агента порождают большие транскрипты. Таблица `sessions` хранит только
`transcript_ref` — ссылку на объект, а работа с объектным хранилищем описана в
`internal/blob`. Перед сохранением `internal/redact` удаляет секреты из текста.

## Решение

Хранить транскрипты как объекты в S3-совместимом хранилище (в dev — RustFS из
`docker-compose.yml`), а в PostgreSQL оставлять метаданные сессии и ссылку.
Тяжёлый контент не попадает в реляционную базу.

## Последствия

- База остаётся компактной, а транскрипты доступны по ссылке из консоли.
- Маскировка секретов выполняется до записи, что снижает риск утечки.
- Объектное хранилище не поддерживает реляционные запросы, поэтому статистика
  по содержимому сессий ведётся по метаданным в базе.
