
# Локальное приложение в Docker

В окружениях проекта выберите «локальный Docker», укажите порт приложения и
путь проверки, затем нажмите «Опубликовать». Rivet сам подготовит Dockerfile
по рецепту Go, Node.js или статического сайта. Ручные команды, Dockerfile,
nginx-конфигурация и registry-токены в настройках окружения не нужны.
Приложение получает `PORT`, `HOST=0.0.0.0` и каталог `/data` на именованном
томе. Переменные формы открытые, секреты в них не передавайте.

Адрес вида `127.0.0.1:20xxx` появляется в карточке после проверки запуска.
Он доступен только на машине Docker-runner-а. При обновлении адрес меняется:
новое поколение сначала проверяется рядом со старым. Неудачная сборка
сохраняет прежнюю работающую версию, показывает причину и ставит
автопубликацию на паузу. После исправления возобновите окружение.

«Перезапустить» сохраняет образ, адрес и данные. «Остановить» выключает
автоматический запуск контейнера, сверка его не поднимает. Следующая ручная
публикация снова запускает приложение. Перед удалением окружения остановите
его: Rivet очистит его контейнеры, образы и том через очередь, затем удалит
записи. Другие Docker-объекты очистка не затрагивает.

Для установки нужен отдельный runner с capabilities `deploy,docker`,
подключённый к локальному Docker на той же машине. Этот runner работает без
LLM и отказывается исполнять shell-задания окружений. Он использует обычную
регистрацию runner-ов и подключение SCM установки. Кодинг-агентам доступ к
Docker socket не требуется.

Если на установке настроен такой runner, первый рабочий Epic автоматически
создаёт локальный стенд с портом приложения 8080, когда у проекта ещё нет
окружения. Инженер по выпуску параллельно с разработкой проверяет Docker и
готовит базовые образы. До первого проверенного merge консоль честно
показывает ожидание артефакта. Merge во время подготовки не теряется, он
публикуется после её завершения. Уже настроенные окружения сохраняются.

Рецепты и сквозной сценарий проверяются командой
`RIVET_DOCKER_TEST=1 go test ./internal/localdocker ./internal/runner -run 'TestDocker|TestLocalDockerAPIToContainer'`.
Каждый тест создаёт собственную БД/контейнеры и убирает только свою фикстуру.
Перезапуск самого Docker проверяется отдельным тестом только на одноразовой
VM GitHub Actions, общий Docker рабочей машины тест не перезапускает.
