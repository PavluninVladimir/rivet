
# Локальное приложение в Docker

В окружениях проекта выберите «локальный Docker», укажите порт приложения и
путь проверки, затем нажмите «Опубликовать». Rivet сам подготовит Dockerfile
по рецепту Go, Node.js или статического сайта. Ручные команды, Dockerfile,
nginx-конфигурация и registry-токены в настройках окружения не нужны.
Приложение получает `PORT`, `HOST=0.0.0.0` и каталог `/data` на именованном
томе. Переменные формы открытые, секреты в них не передавайте.

Для паролей и ключей после создания окружения откройте «Секреты приложения».
Администратор вводит имя, например `ADMIN_PASSWORD`, и скрытое значение.
Консоль очищает значение после сохранения и показывает только имя с маской.
Новая публикация получает снимок секретов на момент постановки в очередь.
Для применения замены или удаления нужна новая публикация, перезапуск
существующего контейнера сохраняет прежние значения. Имена публичных и
секретных переменных не могут совпадать.

Секреты и их снимки шифруются `RIVET_SECRET_KEY`. Без ключа запись запрещена.
Они не передаются coding/review-агентам, сборке образа и в аргументах Docker.
Для поколений с секретами сырой вывод Docker и приложения скрыт целиком,
включая live-поток. Статусы стадий остаются доступны. Значения получает
назначенный runner с capabilities ровно `deploy,docker`, feature
`local_docker_secrets_v1` и защищённым каналом (TLS или loopback).
Старый runner такие поколения не получает. На хосте runner-а временный
env-file имеет права `0600`, создаётся вне рабочей копии после сборки и
удаляется при завершении операции. Администратор Docker-хоста и само
приложение имеют доступ к runtime env, это доверенная граница.
При принудительном завершении процесса временный файл может остаться в
системном tmp с доступом только владельцу runner-а.

После принятия PR backend применит добавочную миграцию `0049` при старте.
Ротация ключа установки перешифровывает и текущие значения, и снимки.
Старые клиенты и окружения без секретов сохраняют совместимость.
При обновлении сначала дождитесь свободного Docker runner-а и переведите
его в draining. Соберите и замените только его бинарник с сохранением ID,
токена, TLS и рабочего каталога. Затем обновите control plane, проверьте
миграцию и новую feature runner-а, снимите draining. Coding/review runner-ы
не требуют замены, но перезапуск control plane может прервать их gRPC-сессии,
поэтому выполняйте его в согласованное окно после активных задач.
После слияния `rivet-web` отдельным коммитом выполните `make ui-sync`,
проверьте `make ui-check` и обновите встроенную консоль. Секреты вводите
через форму только после этой проверки, затем публикуйте новое поколение.
Откат control plane на старую версию после ввода секретов небезопасен:
она не учитывает секретные снимки. Перед таким откатом остановите
публикацию секретных поколений и сохраните актуальную версию Docker runner-а.

Адрес вида `127.0.0.1:20xxx` появляется в карточке после проверки запуска.
Он доступен только на машине Docker-runner-а. При обновлении адрес меняется:
новое поколение сначала проверяется рядом со старым. Неудачная сборка
сохраняет прежнюю работающую версию, показывает причину и ставит
автопубликацию на паузу. После исправления возобновите окружение.

«Перезапустить» сохраняет образ, адрес и данные. «Остановить» выключает
автоматический запуск контейнера, сверка его не поднимает. Следующая ручная
публикация снова запускает приложение. Перед удалением окружения остановите
его: Rivet очистит его контейнеры, образы и том через очередь, затем удалит
записи. Другие Docker-объекты очистка не затрагивает.

Для установки нужен отдельный runner с capabilities `deploy,docker`,
подключённый к локальному Docker на той же машине. Этот runner работает без
LLM и отказывается исполнять shell-задания окружений. Он использует обычную
регистрацию runner-ов и подключение SCM установки. Кодинг-агентам доступ к
Docker socket не требуется.

Если на установке настроен такой runner, первый рабочий Epic автоматически
создаёт локальный стенд с портом приложения 8080, когда у проекта ещё нет
окружения. Инженер по выпуску параллельно с разработкой проверяет Docker и
готовит базовые образы. До первого проверенного merge консоль честно
показывает ожидание артефакта. Merge во время подготовки не теряется, он
публикуется после её завершения. Уже настроенные окружения сохраняются.

Рецепты и сквозной сценарий проверяются командой
`RIVET_DOCKER_TEST=1 go test ./internal/localdocker ./internal/runner -run 'TestDocker|TestLocalDockerAPIToContainer'`.
Каждый тест создаёт собственную БД/контейнеры и убирает только свою фикстуру.
Перезапуск самого Docker проверяется отдельным тестом только на одноразовой
VM GitHub Actions, общий Docker рабочей машины тест не перезапускает.
