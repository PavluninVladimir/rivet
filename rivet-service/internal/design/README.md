# Дизайн-система: формат и изолированный снимок

`rivet.design/v1` содержит только данные: типизированные свойства, стабильные UUID, tokens, компоненты и экраны. Импорт не исполняет React, HTML, CSS или JavaScript. PNG/JPEG хранятся в приватном object storage. API выдаёт отдельные asset-scoped ссылки на пять минут, проверяет актуальное членство выдавшего их пользователя при каждом чтении. Capability URL нельзя включать в публичные логи и внешние ссылки.

PostgreSQL хранит immutable revisions, комментарии и handoff. Сохранение требует текущую revision и Idempotency-Key. Повтор ключа с другим телом отклоняется. Undo создаёт новую revision и отклоняет конфликтующие более поздние изменения. Удалённый UUID нельзя использовать для нового элемента. Восстановление исходного элемента через undo сохраняет его UUID и привязки комментариев.

Детерминированный export содержит `{document,model,assets}` без временных URL. Для preview изображения запрашиваются через отдельный GET asset metadata. Handoff содержит фиксированный manifest SHA, model SHA, snapshot веток и screenshot первого экрана при его собственном viewport. Остальные экраны сохраняются в модели пакета. Git commit SHA не равен content SHA: связь принимается только после чтения `design/rivet/<document_id>/manifest.json` именно на указанном полном commit SHA и проверки `manifest_sha`. Этот endpoint не делает push или merge.

`api.NewDesignScreenshotRenderer` подключает настоящий Chromium. Переменная `RIVET_DESIGN_CHROMIUM_PATH` может задать путь к бинарнику. Renderer строит собственный HTML из валидированной модели, экранирует текст, принимает только разрешённые свойства и inline PNG/JPEG bytes. Сетевых URL и пользовательских scripts в нём нет. Каждый вызов получает отдельный приватный temporary profile, closed CSP, отключённый JavaScript и сетевой resolver, deadline 15 секунд. Размер PNG ограничен 10 МиБ и 4096×4096. Chromium sandbox не отключается. Неудача renderer или object storage даёт явную 503; placeholder не считается screenshot.

Runtime должен позволять работу Chromium sandbox от непривилегированного пользователя. При запрете user namespaces системной политикой renderer остаётся недоступен. Нельзя обходить эту ошибку флагом `--no-sandbox` или privileged-контейнером. Изменения deployment policy требуют отдельной проверки в целевом окружении.

Rollback отключает editor/screenshot capability, сохраняя таблицы и историю. Additive migration не удаляет существующие проекты. API не даёт комментариям права на изменения кода или автоматический merge. Связь с исследованием/задачей не запускает существующий pipeline в обход его собственных guards.

Проверки: `go test ./internal/design`, `go test ./internal/store ./internal/api -run '^TestDesign'`. Store/API tests создают отдельную временную БД и не изменяют рабочую. Для реального native screenshot: `RIVET_DESIGN_CHROMIUM_TEST=/absolute/path/to/chromium go test ./internal/design -run TestChromiumRealScreenshot -v`. Приёмка runtime требует того же теста в конечном nonroot Docker-образе.

## Проверенный Docker sandbox profile

Штатный Docker seccomp на локальном OrbStack запретил Chromium создание namespace (`Operation not permitted`). Запуск со штатной политикой завершился безопасным отказом, а не отключением sandbox. Изолированный nonroot fixture прошёл с `scripts/design-chromium-seccomp.json`: актуальный [Moby default](https://github.com/moby/profiles/blob/9ee3204f0d0cfa19ca2c6a7b0fcf5a2b353954ae/seccomp/default.json) и единственное дополнительное allow-правило для `clone`, `setns`, `unshare`, как описано в [Playwright Docker guide](https://playwright.dev/docs/docker). Default action остаётся `SCMP_ACT_ERRNO`. Исходный и итоговый SHA256 находятся рядом в `design-chromium-seccomp.provenance.json`. Profile vendored и не скачивается при запуске.

Повторение fixture: `scripts/check-design-screenshot.sh rivet-design-workspace:982-alpine324`. Скрипт собирает Linux test binary нужной архитектуры и запускает его в указанном конечном образе, от пользователя образа, без сети, с read-only FS, отдельным tmpfs 256 МиБ, лимитами 1 GiB/2 CPU. Не использует `privileged`, `SYS_ADMIN`, `unconfined`, `--no-sandbox` или пользовательские данные. Проверенный образ работает от `rivet:rivet`; добавление Chromium увеличивает его размер примерно до 1.1 GiB.

Это **опциональная проверенная конфигурация**, не автоматическое изменение политики рабочего стенда. Она добавляет возможность создавать nested namespaces и должна пройти review политики целевого окружения. Старый Playwright JSON profile на этом современном ARM64/runc оказался несовместим до запуска приложения, поэтому используется современный Moby default с тем же минимальным дополнительным правилом. `cap-drop ALL` вместе с `no-new-privileges` на данном fixture пока не прошёл: такую конфигурацию нельзя объявлять проверенной и нельзя компенсировать отключением Chromium sandbox. Для окружения с иными ограничениями нужен отдельный проверенный sandbox runtime или явная недоступность screenshot.

## Передача пакета в назначенную задачу

`Store.DesignTaskContext` добавляет кодеру, ревьюеру и остальным стадиям одну и ту же read-only проекцию зафиксированного handoff. Источники связи: `context_refs` при создании пакета и отдельная аудируемая `task` link record. Оба пути требуют тот же проект, повторная связь не дублирует пакет. При чтении заново проверяются model SHA и immutable manifest SHA. Последующие правки документа не меняют переданную revision.

В контексте есть полная структурная модель, выбранный snapshot обсуждения, SHA/revision, приватные asset metadata без URL/object-storage адресов, а также путь `design/rivet/<document_id>/manifest.json` и полный Git commit SHA, если его связь ранее проверена SCM. В этом блоке нет исполняемых tools, shell, browser session или разрешения на push/merge. Комментарии помечены недоверенными данными и не меняют task/process guards.

Ограничение: до трёх полных пакетов, до 256 КиБ суммарных исходных snapshots (проверяется до их загрузки) и 256 КиБ на весь блок с JSON envelope и инструкцией о недоверенных данных. Четвёртый пакет или превышение размера дают явную `size_limit`, а не выбор первых пакетов или обрезку модели. Диспетчер оставляет задачу в ожидании с объяснением: создать новую задачу с выбранными пакетами либо использовать проверенный Git-артефакт. Сам факт ссылки на Git не разрешает скрытое удаление данных из контекста.

Из обратной связи удаляются распознаваемые credential patterns, session/capability/signed URLs и private-key blocks. `redacted_paths` явно указывает изменённые фрагменты обсуждения; исходный manifest SHA остаётся provenance оригинала, а не digest санитизированного JSON envelope. Источник в БД не меняется. Авторитетная модель никогда не меняется скрытно: при обнаружении таких данных внутри model dispatcher получает `sensitive_design_context`, пустую строку контекста и требование создать санитизированную revision/новый handoff. Pattern redaction не заменяет проверку владельцем произвольных чувствительных данных и корпоративную DLP.


Runtime-base обновлён на [Alpine 3.24, текущую stable-ветку с поддержкой community](https://www.alpinelinux.org/releases/). Браузер относится к community; двухлетняя поддержка main старой ветки не означает поддержку её браузера. Digest официального образа проверен в registry и закреплён в Dockerfile. На дату проверки [каталог пакетов](https://pkgs.alpinelinux.org/packages?branch=v3.24&name=chromium) показывает Chromium 156.0.8078.79-r0. Реальная версия образа и sandbox fixture фиксируются при сборке; это профилактическое обновление, без обещания отсутствия CVE. При обновлениях безопасности нужны свежая сборка APK-слоя, пересмотр runtime digest и повторение fixture; старый Docker build cache нельзя считать проверкой актуальности браузера.


Финальная проверка текущего runtime: Alpine 3.24, фактический APK `chromium-156.0.8078.79-r0`, пользователь `rivet:rivet`. Nonroot fixture с указанным seccomp profile проверяет не только размер PNG 320×240: canvas должен иметь `#102030` в точках (2,2)/(310,230), кнопка `#3498db` в (30,30). Тот же тест проходит native Chromium. Blank PNG не принимается. Для статического HTML отключены ненужные GPU shader cache/compositing/WebGL/Vulkan и закреплён sRGB; Chromium sandbox, GPU sandbox и renderer sandbox не отключаются. Процесс получает только минимальный allowlist PATH/LANG/TZ/HOME/TMP/XDG, без наследования environment control plane, proxy credentials или loader-injection переменных.
