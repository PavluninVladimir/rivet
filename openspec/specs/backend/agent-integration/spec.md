# backend/agent-integration Specification

## Purpose

Определяет единый протокол подключения внешних coding-агентов к Rivet — общий для runner'ов оркестратора и интерактивных сессий людей — и адаптеры разной глубины: нативный плагин агента, универсальная CLI-обёртка, запуск сессии из интерфейса Rivet.

## Requirements

### Requirement: Единый протокол подключения агентов

Система ДОЛЖНА определять единый протокол подключения агента: регистрация (пользователь или планировщик, тип агента, модель, проект, ветка, заявленный scope), поток событий и транскрипта, отчёт об израсходованных токенах, heartbeat. Runner оркестратора и интерактивная сессия человека ДОЛЖНЫ использовать один и тот же протокол; их события пишутся в общий event log.

#### Scenario: Оркестрированная задача и живая сессия в одном логе

- **WHEN** планировщик выполняет задачу на runner'е, а участник команды параллельно ведёт интерактивную сессию в том же проекте
- **THEN** события обоих подключений появляются в event log проекта в едином формате с указанием водителя (scheduler / пользователь)

### Requirement: Уровни глубины данных

Система ДОЛЖНА корректно работать с подключениями любой глубины: полной (события, инструменты, затронутые файлы, токены), частичной и минимальной (только транскрипт). Отсутствующие данные ДОЛЖНЫ отображаться как недоступные для данного способа подключения, а не как ошибка; функции, требующие недостающих данных (например, расчёт пересечений по файлам), явно сообщают о причине недоступности.

#### Scenario: Сессия через универсальную обёртку

- **WHEN** агент подключён через CLI-обёртку, дающую только транскрипт
- **THEN** сессия видна команде с транскриптом и длительностью, а поля «затронутые файлы» и «токены» помечены как недоступные для этого способа подключения

### Requirement: Официальные адаптеры

Система ДОЛЖНА предоставлять как минимум: нативный плагин для одного распространённого CLI-агента (первый — Claude Code, через его механизм хуков) с полной глубиной данных и универсальную обёртку для запуска любого CLI-агента с минимальной глубиной.

#### Scenario: Подключение без нативного плагина

- **WHEN** участник команды запускает агента, для которого нет нативного плагина, через универсальную обёртку
- **THEN** сессия регистрируется в Rivet и видна команде с минимальной глубиной данных

### Requirement: Сессия из интерфейса Rivet

Пользователь ДОЛЖЕН иметь возможность запустить сессию агента из интерфейса Rivet (включая мобильные клиенты): систему исполнения предоставляет Rivet (локальный демон или управляемый runner), данные сессии доступны с полной глубиной.

#### Scenario: Сессия с телефона

- **WHEN** пользователь отвечает на эскалацию с мобильного клиента и запускает короткую сессию доработки
- **THEN** сессия выполняется на доступном runner'е, её ход виден в реальном времени, а результат проходит обычный конвейер проверок

### Requirement: Открытый SDK адаптеров

Протокол подключения и SDK адаптеров ДОЛЖНЫ быть публичными: сторонний разработчик может создать адаптер для своего агента без изменения ядра системы.

#### Scenario: Сторонний адаптер

- **WHEN** сторонний адаптер, реализующий протокол, подключается к системе
- **THEN** его сессии регистрируются и отображаются наравне с сессиями официальных адаптеров

### Requirement: Обратный канал контекста

Протокол ДОЛЖЕН поддерживать доставку контекста от Rivet агенту: описание и acceptance criteria задачи, предупреждения о пересечениях scope, релевантные знания проекта. Адаптеры, не поддерживающие обратный канал, ДОЛЖНЫ работать в режиме «только отправка» без потери остальной функциональности.

#### Scenario: Предупреждение о пересечении в сессии

- **WHEN** scope интерактивной сессии пересекается с выполняющейся задачей оркестратора и адаптер поддерживает обратный канал
- **THEN** агент в сессии получает предупреждение о пересечении и может сообщить его пользователю
