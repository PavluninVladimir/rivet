# backend/epic-decomposition Specification

## Purpose

Определяет, как Epic превращается в план: декомпозиция на небольшие задачи с зависимостями и acceptance criteria, построение DAG и утверждение плана человеком до запуска.

## Requirements

### Requirement: Создание Epic человеком

Пользователь ДОЛЖЕН создавать Epic, указав цель (описание того, что нужно сделать), целевой репозиторий и, при необходимости, ограничения (сроки, бюджет токенов, обязательные проверки).

#### Scenario: Создание Epic

- **WHEN** пользователь создаёт Epic с описанием и репозиторием
- **THEN** Epic появляется в статусе «не запущен» и доступен для декомпозиции

### Requirement: Автоматическая декомпозиция Epic

Система ДОЛЖНА декомпозировать Epic на небольшие задачи с помощью модели: каждая задача получает заголовок, описание, acceptance criteria, зависимости и требуемые capabilities. Из зависимостей строится DAG выполнения.

#### Scenario: Декомпозиция выполнена

- **WHEN** пользователь запускает декомпозицию Epic
- **THEN** система создаёт набор задач с зависимостями, образующими ациклический граф, и показывает его пользователю

#### Scenario: Некорректный план не принимается

- **WHEN** модель вернула план с циклом, дублями или задачей без acceptance criteria
- **THEN** система не принимает план: перезапускает генерацию либо показывает пользователю конкретные дефекты плана

### Requirement: Утверждение плана до запуска

Построенный план ДОЛЖЕН быть показан человеку на проверку. Выполнение НЕ ДОЛЖНО начинаться до явного запуска Epic человеком.

#### Scenario: Запуск после проверки

- **WHEN** пользователь просмотрел план и нажал «Start Epic»
- **THEN** оркестратор переводит задачи без зависимостей в `ready` и начинает планирование

### Requirement: Правка плана человеком

Пользователь ДОЛЖЕН иметь возможность править план: добавлять и удалять задачи, менять описания, acceptance criteria и зависимости — как до запуска, так и по ходу выполнения (для ещё не начатых задач).

#### Scenario: Добавление задачи в работающий Epic

- **WHEN** пользователь добавляет задачу с зависимостями в запущенный Epic
- **THEN** задача встраивается в DAG и планируется по общим правилам, не затрагивая уже идущие задачи
