# clients/mobile Specification

## Purpose

Определяет мобильные клиенты (нативные Android и iOS): наблюдение за проектами и Epic'ами, push-уведомления об эскалациях, действия с телефона — ответ на эскалацию, управление Epic, запуск публикации и короткой сессии.

## Requirements

### Requirement: Паритет состояния с консолью

Мобильные клиенты ДОЛЖНЫ работать через тот же API и показывать то же состояние системы, что и веб-консоль: проекты, Epic'и с прогрессом и статусами задач, runner'ы, лента активности, usage. Мобильный клиент МОЖЕТ упрощать представления (например, список задач вместо полного DAG-графа), но НЕ ДОЛЖЕН показывать состояние, отличное от консоли.

#### Scenario: Одинаковое состояние

- **WHEN** пользователь открывает Epic в консоли и в мобильном приложении одновременно
- **THEN** статусы задач, прогресс и эскалации совпадают

### Requirement: Push-уведомления об эскалациях

Мобильный клиент ДОЛЖЕН доставлять push-уведомления о событиях, требующих человека: новая эскалация (blocked, review limit, test failed), провал публикации, исчерпание бюджета. Набор событий и проекты ДОЛЖНЫ настраиваться пользователем.

#### Scenario: Эскалация приходит пушем

- **WHEN** задача переходит в `blocked` с вопросом к человеку
- **THEN** участники проекта получают push с сутью вопроса, открывающий деталку эскалации

### Requirement: Действия с телефона

Мобильный клиент ДОЛЖЕН позволять ключевые действия без консоли: ответить на эскалацию (уточнить критерии, разрешить повтор, отменить задачу), взять эскалацию в работу, запустить/приостановить Epic, запустить ручную публикацию в окружение, запустить короткую сессию агента (через управляемый runner).

#### Scenario: Разблокировка задачи в дороге

- **WHEN** пользователь отвечает на вопрос заблокированной задачи из push-уведомления
- **THEN** задача возвращается в работу, а решение фиксируется в event log с идентичностью пользователя

#### Scenario: Prod кнопкой с телефона

- **WHEN** пользователь запускает ручную публикацию в prod из мобильного клиента
- **THEN** публикация проходит обычные этапы Deploy → Verify, ход виден в приложении

### Requirement: Наблюдение за live-работой

Мобильный клиент ДОЛЖЕН показывать живой ход выполняющейся задачи или сессии (шаги агента, ключевые события) в реальном времени; полный терминальный вывод МОЖЕТ быть упрощён до просмотра по запросу.

#### Scenario: Наблюдение за задачей с телефона

- **WHEN** пользователь открывает выполняющуюся задачу в приложении
- **THEN** он видит текущие шаги агента и события задачи, обновляющиеся без ручного обновления экрана
