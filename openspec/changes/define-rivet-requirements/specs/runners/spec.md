## Purpose

Определяет runner'ы — исполнителей задач: комбинацию coding-агента, модели и окружения на конкретном хосте, с capabilities, статусом и контролем контекста.

## ADDED Requirements

### Requirement: Регистрация runner'а

Runner ДОЛЖЕН регистрироваться в системе с атрибутами: идентификатор, тип агента (Claude Code, Codex, Pi.dev, OpenCode и др.), модель, хост и набор capabilities (например, `coding`, `frontend`, `review`, `cheap`, `local`, `large-context`). Разные runner'ы МОГУТ использовать разных агентов, модели и окружения.

#### Scenario: Список runner'ов

- **WHEN** пользователь открывает раздел Runners
- **THEN** он видит все runner'ы с агентом, моделью, хостом, статусом, текущей задачей и capabilities

### Requirement: Один runner — одна задача

Runner ДОЛЖЕН выполнять не более одной задачи единовременно. Освободившись, runner становится доступен планировщику.

#### Scenario: Runner освободился

- **WHEN** runner завершил этап своей задачи и стал `idle`
- **THEN** планировщик может немедленно назначить ему следующую подходящую `ready`-задачу

### Requirement: Мониторинг контекста и расхода

Система ДОЛЖНА отслеживать для занятого runner'а заполненность контекста модели (в процентах) и израсходованные токены и показывать их пользователю. Превышение порога заполненности ДОЛЖНО подсвечиваться.

#### Scenario: Контекст почти заполнен

- **WHEN** заполненность контекста runner'а превышает порог (например, 60 %)
- **THEN** индикатор контекста подсвечивается как критичный

### Requirement: Управление доступностью runner'а

Пользователь ДОЛЖЕН иметь возможность выводить runner из ротации (drain: доработать текущую задачу и не брать новые) и возвращать его в ротацию.

#### Scenario: Вывод из ротации

- **WHEN** пользователь отключает runner
- **THEN** runner дорабатывает текущую задачу, новые задачи ему не назначаются
