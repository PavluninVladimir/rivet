## Purpose

Определяет консоль управления Rivet — единый интерфейс наблюдения и принятия решений. Эталон UX и визуального языка — дизайн-прототип `agent-orchestration-console.html`.

## ADDED Requirements

### Requirement: Основные представления

Консоль ДОЛЖНА предоставлять представления: Projects, Epics (список с прогрессом), дашборд Epic, Tasks (сквозной список с фильтрами), Runners, Activity, Usage, Settings. Навигация между ними — через боковую панель; счётчик эскалаций виден из любого представления.

#### Scenario: Переход к эскалации

- **WHEN** пользователь видит в навигации счётчик задач, требующих внимания
- **THEN** он переходит к списку эскалаций не более чем за один клик

### Requirement: Дашборд Epic с DAG

Дашборд Epic ДОЛЖЕН показывать: заголовок с прогрессом и статусами задач, блок «needs attention», DAG задач в виде графа (пан/зум, подсветка критического пути, фильтры по статусу, скрытие завершённых) и альтернативный табличный вид, а также панель runner'ов с их текущим состоянием.

#### Scenario: Работа с графом

- **WHEN** пользователь открывает дашборд Epic
- **THEN** он видит DAG задач со статусами и исполнителями, может масштабировать граф, включить подсветку критического пути и отфильтровать задачи по статусу

### Requirement: Деталка задачи

По клику на задачу консоль ДОЛЖНА открывать панель деталей: атрибуты (runner, модель, ветка, PR, попытки, токены), acceptance criteria с их статусом, timeline событий, live-шаги и терминальный вывод для выполняющейся задачи, а также доступные действия (открыть PR, повторить, отменить, ответить на вопрос).

#### Scenario: Разбор заблокированной задачи

- **WHEN** пользователь открывает заблокированную задачу
- **THEN** он видит вопрос агента, историю событий и действие для ответа/разблокировки

### Requirement: Командная палитра

Консоль ДОЛЖНА предоставлять командную палитру (⌘K): поиск по задачам, Epic'ам и runner'ам и быстрые команды (переходы, действия над Epic). Результат открывается без потери текущего контекста.

#### Scenario: Быстрый переход к задаче

- **WHEN** пользователь вводит в палитре идентификатор задачи
- **THEN** консоль открывает деталку этой задачи

### Requirement: Соответствие дизайн-прототипу

Реализация консоли ДОЛЖНА следовать дизайн-прототипу `agent-orchestration-console.html`: состав представлений, статусная цветовая система, плотность информации. Отклонения от прототипа ДОЛЖНЫ фиксироваться осознанно (в design-документах соответствующих изменений).

#### Scenario: Сверка с эталоном

- **WHEN** реализуется экран, присутствующий в прототипе
- **THEN** его состав и поведение сверяются с прототипом, а отличия документируются
