## Why

Rivet сейчас существует в виде видения (CLAUDE.md) и дизайн-прототипа консоли (`agent-orchestration-console.html`). Прежде чем писать код, нужно превратить видение и дизайн в проверяемые требования: зафиксировать доменную модель, правила оркестрации, жизненный цикл задачи и точки участия человека. Без этого декомпозиция на инженерные эпики будет произвольной, а прототип останется единственным носителем знаний о продукте.

## What Changes

- Из дизайн-прототипа и видения извлекается и фиксируется доменная модель: Project → Epic → Task, DAG зависимостей, статусная модель задач и runner'ов.
- Формулируются требования к оркестрации: декомпозиция Epic на задачи, планирование по DAG, подбор runner'а по capabilities, retry и лимиты попыток.
- Фиксируется конвейер задачи Coding → Tests → Review → Fix → Merge с независимым review-агентом.
- Описываются правила эскалации человеку (needs attention): когда Rivet останавливается и ждёт решения.
- Формулируются требования к наблюдаемости: event log всех действий и учёт usage (токены, стоимость).
- Фиксируются требования к консоли управления на основе прототипа.
- Составляется план работ по доводке требований: открытые вопросы, приоритизация MVP, критерии готовности спецификаций.

Кода это изменение не затрагивает — результатом являются спецификации в `openspec/specs/` и план их доводки.

## Capabilities

### New Capabilities

- `domain-model`: сущности Project, Epic, Task, Runner; DAG зависимостей; статусные модели и допустимые переходы.
- `epic-decomposition`: декомпозиция Epic на небольшие задачи с зависимостями и acceptance criteria; построение DAG; пересмотр плана человеком до запуска.
- `orchestration`: детерминированный планировщик — готовность задач, параллельный запуск независимых задач, подбор runner'а по capabilities, retry, лимиты попыток, реакция на сбои зависимостей.
- `task-pipeline`: жизненный цикл одной задачи — реализация, тесты и автопроверки, независимое review, возврат на исправление, merge; изоляция в ветке `agent/task-N` и PR.
- `runners`: реестр исполнителей — агент, модель, хост, capabilities, статусы, контроль контекста; подключение и отключение runner'ов.
- `human-escalation`: очередь «needs attention» — причины эскалаций (blocked, review limit, test failed, нехватка информации), действия человека и возврат задачи в работу.
- `observability`: event log всех действий (кто, что, когда, в рамках чего) и учёт usage — токены и стоимость в разрезе Epic / задачи / runner'а.
- `console`: консоль управления — представления Projects, Epics (DAG и список), Tasks, Runners, Activity, Usage, деталка задачи, командная палитра; эталон — дизайн-прототип.

### Modified Capabilities

Нет — существующих спецификаций в проекте пока нет.

## Impact

- Появляются первые спецификации в `openspec/specs/` (через delta-спеки этого изменения) — они становятся источником истины вместо неявных знаний в прототипе.
- `agent-orchestration-console.html` получает статус эталона UX, на который ссылаются требования `console`.
- Кодовая база, API и зависимости не затрагиваются; изменение готовит почву для последующих инженерных изменений (архитектура, MVP).
