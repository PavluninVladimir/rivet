# local-docker-publish

## Зачем

Локальная публикация сегодня собирается руками. Чтобы посмотреть приложение
на своей машине, пользователь:

- пишет `deploy_cmd` — произвольный shell от имени runner'а
  (`docker build -t app . && docker run -p 8080:8080 …`);
- держит в репозитории Dockerfile и правит его под платформу;
- поднимает nginx или другой reverse proxy, чтобы приложение было доступно
  по привычному адресу;
- выпускает токен runner'а и раскладывает его файлом с правами `0600`, а для
  приватного репозитория передаёт git-токен;
- вручную указывает `verify_url` и потом руками же проверяет, что контейнер
  жив.

Каждый шаг — источник ошибок. Порт публикуется на `0.0.0.0`, и приложение
случайно становится доступно всей сети. Команды и токены никто не проверяет.
После перезапуска Docker или rivetd состояние публикации теряется: в консоли
«зелено», контейнера нет.

Нужна локальная Docker-публикация, у которой нет ни одного ручного шага:
конфигурация из полей формы, Dockerfile и nginx генерирует платформа,
наружу публикация не выходит вообще, состояние хранится в БД и сверяется с
Docker.

## Что меняется

- Новый тип окружения `local_docker` и модель конфигурации
  `LocalDockerEnvironmentConfig` (порт контейнера, путь healthcheck, рецепт
  сборки, каталог сборки, таймауты, переменные окружения приложения).
- Ограничение адреса: публикация только на `127.0.0.1` или `::1`. Адрес
  выбирает платформа из свободных портов, пользователь его не задаёт.
- Платформа сама пишет Dockerfile по рецепту (`go`, `node`, `static`,
  автоопределение) и сама запускает контейнер. Поля `deploy_cmd`,
  `verify_cmd`, `verify_url`, `host` для `local_docker` запрещены — ответ
  422 с указанием поля.
- Публикация как объект: `publish`, `redeploy`, `restart`, `stop`,
  `status`, `logs`. Состояния и переходы — в дельте спеки
  `local-docker-publish`.
- Healthcheck идёт с runner'а по loopback: control plane в loopback не ходит,
  это закрыто фильтром адресов.
- Безопасный redeploy: новый контейнер поднимается рядом со старым,
  проверяется и только потом старый останавливается. Провал сборки или
  проверки оставляет работать прежнюю версию.
- Состояние публикации durable: метки на контейнерах, сверка (reconcile)
  после перезапуска Docker и rivetd, восстановление работы без пересборки.
- Явные запреты: non-loopback listen, shell-команды, ручные
  Dockerfile/nginx/token.

## Чего не делаем

- Внешнего доступа к локальной публикации: доменов, TLS-сертификатов,
  reverse proxy, выхода за loopback. Проброс наружу — задача отдельного
  изменения и отдельного решения по безопасности.
- Доставки секретов в контейнер. Значения из `env` видны в конфигурации
  окружения и журнале, поэтому секреты в них писать нельзя. Хранилище
  секретов публикации — отдельное изменение.
- Registry и тегов образов: образ собирается локально у runner'а и никуда не
  отправляется.
- Нескольких хостов публикации: окружение публикуется на хосте runner'а.
- Отката на произвольную старую версию сверх `redeploy` версии из истории.

## Влияние

- Существующие типы (`ssh`, `k8s`, `pipeline`, `gitops`) не меняются, кроме
  расширения списка допустимых `exec_type` и запрета полей `local_docker` в
  чужих конфигурациях.
- `POST /api/v1/environments/{id}/deploy` для `local_docker` становится
  синонимом `publish`, для остальных типов контракт прежний.
- Наблюдение окружения (`operations`) для `local_docker` проверяет URL с
  runner'а, команды наблюдения запрещены.
- Миграция БД: таблица публикаций локальной доставки и partial unique
  индекс «одна активная публикация на окружение» — как у очереди деплоя.
- Веб-консоль получает карточку публикации с кнопками и логами, без полей
  Dockerfile, nginx и токенов.
- E2E-стенд получает сценарии loopback-only, безопасного redeploy и
  восстановления после перезапуска Docker.

## Риски

- Сборка на runner'е исполняет код репозитория (`go build`, `npm ci`). Риск
  тот же, что у задачи в песочнице runner'а; рецепты фиксированные, команд
  пользователя в них нет.
- Автовыбор порта означает, что `listen` меняется между поколениями
  публикации. Потребители обязаны читать адрес из статуса, а не запоминать
  номер порта. Постоянный порт оставлен открытым вопросом в `design.md`.
